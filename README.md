# stricttf

`stricttf` is a strict subset of Terraform plus a tooling layer that turns
module authoring into a deterministic, machine-readable oracle for LLM code
generation.

It is not a new configuration language, a Terraform fork, a policy engine,
or a replacement for `terraform validate`. It keeps Terraform's syntax and
semantics, then adds a constrained authoring profile and a closed diagnostic
loop for agents.

## Thesis

Terraform already knows how to parse, format, and validate a module. What it
does not provide is a feedback channel an agent can close a loop on: its
output is prose across several commands, `validate` says nothing about
unpinned providers, untyped variables, or literal credentials, and nothing
about a security group open to the world. `stricttf` supplies the missing
channel — one JSON document, stable codes, exact locations, deterministic
ordering — and adds the rules that catch the defects Terraform accepts
happily and a review or an incident only reveals later.

## Install

```bash
cargo install --git https://github.com/ilvar/stricttf
```

Terraform must be on `PATH` for a full check; CI verifies against
**v1.16.5**. When no `terraform` binary is found, an OpenTofu `tofu` binary
is used instead. Modules generated by `stricttf new` need Terraform **1.6+**
for `terraform test`. The repository pins Rust **1.97.1**; ensure
`$HOME/.cargo/bin` is on `PATH`.

### Install the agent skill

```bash
stricttf install-skills
```

Codex is detected from a `codex` executable or `~/.codex`/`~/.agents` and
installed at `~/.agents/skills/stricttf/SKILL.md`; Claude Code from a
`claude` executable or `~/.claude` and installed at
`~/.claude/skills/stricttf/SKILL.md`. Only detected agents are installed
for. The operation is idempotent, accepts an identical existing skill, and
refuses to overwrite a modified one. `cargo install` never touches your home
directory.

## Usage

```bash
stricttf --help                    # the complete embedded agent manual
stricttf check modules/network     # one JSON document on stdout
stricttf fix modules/network       # apply mechanical fixes, then re-check
stricttf new network               # generate a module already in the subset
stricttf install-skills
stricttf modules/network           # a bare path is treated as check
```

A path names one module — the directory whose `*.tf` files Terraform loads
together. Nested module directories are not descended into; check each one.

`--source-only` runs the layers that need no Terraform binary. Without it, a
missing `terraform` is an operational failure rather than a silently reduced
check.

Operational commands emit exactly one JSON document on stdout; `--help` is
the only plain-text stdout mode. Exit `0` means no errors, `1` means errors
remain, `2` means the check did not complete.

## The four layers

A check runs cheapest first, and every layer reports everything it finds
rather than stopping at its first defect.

| Layer | Sees | Needs Terraform |
| --- | --- | --- |
| 1. module structure | syntax, `required_version`, `required_providers`, lock file, `.tfvars` | no |
| 2. configuration source | variables, outputs, module calls, expressions | no |
| 3. resource policy | security defects in literal resource arguments | no |
| 4. terraform | `terraform fmt`, `init -backend=false`, `validate -json`, normalised | yes |

Layer 4 is skipped when layer 1 proves a `.tf` file is not HCL: Terraform's
error for an unparsable file tells an agent strictly less than the located
syntax diagnostic already did.

When a `.tf` file is not HCL, the rules that conclude something is missing
or unused across the whole module (`required_version_missing`,
`provider_undeclared`, `tfvars_undeclared`, `unused_variable`,
`unused_local`) stay silent, because the declaration they would miss may be
in the broken file. Blocks in override files (`override.tf`,
`*_override.tf`) are partial by design and need not repeat a type,
description, source, version, or sensitive flag.

Files read are `*.tf` and `*.tfvars` in the module directory and
`tests/*.tftest.hcl`. JSON configuration (`*.tf.json`) is checked by layer 4
only. Rules that need a value decide only from literals; a value computed
from an expression is never guessed at.

The terraform layer never writes into the module. `.terraform` lives in a
per-module cache under the system temp directory, an existing
`.terraform.lock.hcl` is used read-only (`-lockfile=readonly`), and one that
`init` had to create is removed again afterwards. `init` still downloads the
providers and modules the configuration requires.

## Diagnostic contract

```json
{
  "ok": false,
  "error_count": 1,
  "warning_count": 0,
  "diagnostics": [
    {
      "level": "error",
      "source": "stricttf",
      "code": "stricttf::open_admin_ingress",
      "message": "ingress from 0.0.0.0/0 reaches port 22 (SSH); ...",
      "at": {
        "file": "network.tf",
        "line": 12, "col": 21, "end_line": 12, "end_col": 32,
        "snippet": "    cidr_blocks = [\"0.0.0.0/0\"]"
      },
      "fixes": []
    }
  ]
}
```

Diagnostics are sorted by `(file, line, col, code, message)` and
deduplicated, so two runs over the same module produce byte-identical
output. Lines and columns are 1-based, columns count characters, and
`end_col` points one past the last character. `source` is `stricttf` for a
subset rule and `terraform` for a normalised Terraform finding. Match on
`code`, never on message text.

## The strict subset

### Module structure

| Code | Rejects |
| --- | --- |
| `stricttf::no_configuration` | a directory with no `.tf` files |
| `stricttf::syntax_error` | a `.tf`, `.tfvars`, or `.tftest.hcl` file that is not HCL |
| `stricttf::required_version_missing` | no `terraform { required_version }` |
| `stricttf::provider_undeclared` | a provider used but absent from `required_providers` |
| `stricttf::provider_source_missing` | a `required_providers` entry with no `source` |
| `stricttf::provider_version_missing` | a `required_providers` entry with no `version` |
| `stricttf::provider_version_unbounded` | `>= 5.0` and other constraints with no upper bound |
| `stricttf::lock_file_missing` | providers but no `.terraform.lock.hcl` (warning) |
| `stricttf::tfvars_undeclared` | a `.tfvars` assignment to an undeclared variable |

### Configuration source

| Code | Rejects |
| --- | --- |
| `stricttf::variable_missing_type` | a variable with no `type` |
| `stricttf::variable_missing_description` | a variable with no `description` |
| `stricttf::variable_any_type` | `any` anywhere in a type constraint |
| `stricttf::quoted_type_constraint` | a legacy quoted type such as `"string"` (fixable) |
| `stricttf::sensitive_variable_unmarked` | a credential-named variable without `sensitive = true`, unless typed `bool` or `number` |
| `stricttf::output_missing_description` | an output with no `description` |
| `stricttf::unused_variable` | a variable nothing reads (warning) |
| `stricttf::unused_local` | a local nothing reads (warning) |
| `stricttf::module_version_missing` | a registry module call with no `version` |
| `stricttf::module_version_inexact` | a registry module version range |
| `stricttf::module_ref_missing` | a git module source with no `ref`, or a `ref` naming a branch |
| `stricttf::nondeterministic_function` | `timestamp`, `uuid`, `bcrypt`, `plantimestamp` |
| `stricttf::provisioner` | a `provisioner` block |
| `stricttf::external_program` | `data "external"` |
| `stricttf::interpolation_only` | `"${expr}"` where `expr` alone is meant (fixable) |
| `stricttf::ignore_changes_all` | `lifecycle { ignore_changes = all }` (warning) |
| `stricttf::name_not_snake_case` | a resource, data, module, variable, output, or local name |

### Resource policy

| Code | Rejects |
| --- | --- |
| `stricttf::hardcoded_secret` | a literal credential in configuration or a `.tfvars` file |
| `stricttf::open_admin_ingress` | `0.0.0.0/0` or `::/0` reaching SSH, RDP, or every port |
| `stricttf::public_bucket_acl` | a `public-read`, `public-read-write`, or `authenticated-read` S3 ACL |
| `stricttf::public_database` | `publicly_accessible = true` on a database |
| `stricttf::wildcard_iam_action` | an `Allow` statement granting `"*"` |

A credential name is one whose final segment is `password`, `passwd`,
`passphrase`, or `token`, or is `secret` after at least one other segment
(`client_secret`; a bare `secret` usually names an entry in a secret store),
or whose final two segments are `access_key`, `api_key`, `private_key`,
`secret_key`, or `secret_string`. `password_length` and `secret_arn`
describe a secret without containing one, and the idempotency keys
`creation_token`, `client_token`, and `idempotency_token` hold none.

Terraform's own findings arrive under `terraform::fmt` (fixable),
`terraform::init`, and `terraform::validate`.

## Why these rules

**`interpolation_only`.** `"${var.ports}"` is Terraform 0.11 syntax. A
template holding a single interpolation yields the inner value unchanged, so
the wrapper changes nothing except what a reader believes: it suggests a
string where there may be a list, a map, or a number. `terraform fmt` removes
it as well; `var.ports` says what it means.

**`nondeterministic_function`.** `timestamp()` and `uuid()` return a new
value on every plan, so a resource that uses one never converges: every plan
shows a change, and a reviewer learns to ignore the plan. Calls inside `check`
blocks, `validation` blocks, and pre- or postconditions plan no change and
are allowed.

**`provider_version_unbounded` and `module_version_inexact`.** `>= 5.0`
accepts the next major release the day it ships. A module version range
lets one commit deploy different code on different days. Bound providers,
pin modules, and upgrade on purpose.

**`hardcoded_secret`.** A literal credential lands in version control and,
in plain text, in state. It belongs in a sensitive variable or a secret
store.

## Fixes

Terraform supplies no machine-applicable suggestions beyond its formatter,
so every fix is either `terraform fmt`'s own output or a `stricttf` rule's.
A rule may attach a fix only when the replacement is span-exact,
unambiguous, and idempotent. A rule that would have to guess attaches
nothing.

`stricttf fix` applies edits back to front within each file, deduplicates
identical edits, keeps the first of any overlapping alternatives, refuses any
path outside the module directory, validates byte ranges and UTF-8
boundaries before writing, and re-checks after every pass. It stops when the
report is clean, when no applicable fix remains, when a pass makes no
progress, or after 10 passes.

## Generated modules

`stricttf new <name>` writes a module that already passes `stricttf check`
with no errors and no warnings, plus the workflow that keeps it passing:

```text
versions.tf                     required_version, bounded
variables.tf                    typed, described, validated inputs
main.tf                         provider-free, built on terraform_data
outputs.tf                      described outputs
tests/main.tftest.hcl           terraform test runs, including a rejected input
.github/workflows/ci.yml        the same gate in CI
.pre-commit-config.yaml         the same gate before each commit
Makefile, scripts/check.sh      the same gate locally, naming every skipped stage
.tflint.hcl, .terraform-version third-party tool configuration
.gitignore, AGENTS.md, CLAUDE.md, README.md
```

The scaffold needs no provider and no network, so its gate runs anywhere.
[tflint] is wired in and optional.

[tflint]: https://github.com/terraform-linters/tflint

## Development

`stricttf` is written in Rust in the [`strictrs`](https://github.com/ilvar/strictrs)
strict subset, and its own CI enforces that: no `unsafe`, no panic APIs
outside tests, no numeric `as` casts, explicit return types, and every
filesystem and process effect confined to a marked capability module.

```bash
cargo fmt --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --all-targets --all-features --locked
strictrs check .
```

| Suite | Covers |
| --- | --- |
| `tests/source_layer.rs` | module-structure and configuration-source rules |
| `tests/resource_layer.rs` | resource-policy rules |
| `tests/terraform_parsing.rs` | normalisation of Terraform's output, against captured goldens |
| `tests/terraform_live.rs` | end to end against a real Terraform binary |
| `tests/fix_loop.rs` | fix application, refusal, and termination |
| `tests/pipeline.rs` | layer orchestration, reading, and report ordering |
| `tests/generator.rs` | the generated-module contract |
| `tests/cli.rs` | exit codes and stdout/stderr separation |
| `tests/help.rs` | the embedded manual, checked against the emitted code set |
| `tests/skills.rs` | skill installation, in an isolated fake home |

`tests/terraform_live.rs` skips when Terraform is absent, but never silently:
CI sets `STRICTTF_REQUIRE_TERRAFORM=1`, which turns a skip into a failure.

See [`AGENTS.md`](AGENTS.md) for repository-specific implementation rules.

## Non-goals

A new configuration language, a Terraform fork, a policy language,
plan-time or state-reading checks, and anything needing cloud credentials
are explicit non-goals. `stricttf` reports; it does not apply.
